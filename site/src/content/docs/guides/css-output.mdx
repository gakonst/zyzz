# CSS Output

Choose whether Zyzz writes one class per declaration or one class per style.

## Overview

The compiler turns each reachable style into CSS ahead of time, and `cssOutput` decides how declarations become classes. Applying a style returns class names and never inserts CSS rules.

Set the mode in the config. It applies to config-bound helpers. Helpers imported directly from `zyzz` use the integration's mode instead, which is atomic unless an integration such as Babel sets `cssOutput`.

```ts title="zyzz.config.ts"
import { defineConfig } from 'zyzz'

export const { style, variants } = defineConfig({
  // [!code hl:2]
  // Atomic output is the default, so this option is optional
  cssOutput: 'atomic',
})
```

## Atomic Output

Each declaration becomes its own class, and a fallback array, such as `display: ['block', 'grid']`, stays together in one class. Styles share a class when reuse keeps precedence. The card and label below are each spread alone onto an element, so their classes never combine and they share `color: red`.

```tsx title="Card.tsx"
import { style } from './zyzz.config.js'

export function Card() {
  return (
    <article {...styles.card()}>
      <span {...styles.label()}>Account</span>
    </article>
  )
}

namespace styles {
  // [!code hl:5]
  // Atomic classes: z_X8T0-w0 z_X8T0-w1
  export const card = style({ color: 'red', padding: '8px' })

  // Atomic classes: z_X8T0-w0
  export const label = style({ color: 'red' })
}
```

```css title="atomic.css"
/* [!code hl:4] */
/* Shared by the card and label */
.z_X8T0-w0 {
  color: red;
}

/* Used by the card only */
.z_X8T0-w1 {
  padding: 8px;
}
```

Production builds name these rules with a module hash and a counter, and development builds use readable names that start with the module hash, such as `z-X8T0-w-text-red`. Styles whose classes can combine, such as exported styles, share a class only when no style defined between them sets that property differently.

Each module delivers its own stylesheet, and a rule repeated in a later stylesheet takes that later position. The module hash therefore keeps two modules from sharing a rule, so an override from a consuming module still wins.

The compiler proves from source that these classes never combine. Classes added to the same element through DOM APIs, such as `classList.add`, can therefore lose definition order, so combine styles with `cx` instead.

## Grouped Output

Each style becomes one class. Switch the config to grouped output, and the same card compiles to one class per style.

```ts title="zyzz.config.ts"
import { defineConfig } from 'zyzz'

export const { style, variants } = defineConfig({
  // [!code hl:2]
  // Emit one class per style instead of one per declaration
  cssOutput: 'grouped',
})
```

Production names combine a module hash with a counter, so modules can reuse member names without collisions. Development builds name each class after its member path instead, such as `z-X8T0-w-styles-card`.

```css title="grouped.css"
/* [!code hl:5] */
/* Generated for styles.card */
.z_X8T0-w0 {
  color: red;
  padding: 8px;
}

/* Generated for styles.label */
.z_X8T0-w1 {
  color: red;
}
```

Neither mode guarantees smaller or faster output, so compare CSS, JavaScript, and markup sizes for the application. The [benchmarks](/docs/introduction/benchmarks) use grouped output.

## Overrides

Both modes preserve cascade behavior, and atomic classes are shared only when reuse keeps precedence. Combine styles with `cx`, since multiple JSX spreads replace each other's styling props.

```tsx title="CompactCard.tsx"
import { cx } from 'zyzz'
import { style } from './zyzz.config.js'

export function CompactCard() {
  // [!code hl:2]
  // Later arguments win, so the compact padding replaces the card's
  return <article {...cx(styles.card(), styles.compact())}>Account</article>
}

namespace styles {
  export const card = style({ color: 'red', padding: '8px' })

  export const compact = style({ padding: '4px' })
}
```

Class-string order does not determine precedence. `cx` also preserves variable bindings and variant attributes, and dynamic values bind to precompiled custom properties.

## Independent Composition

Set `composition: 'independent'` when every style combines only through `cx`, including exported styles and styles passed to other components. Their atomic rules then share short names as well, even when another style sets a different value.

```ts title="zyzz.config.ts"
import { defineConfig } from 'zyzz'

export const { style } = defineConfig({
  // [!code hl:2]
  // Styles combine only through cx, so repeated declarations share rules
  composition: 'independent',
})
```

Ordered output resolves conflicts between combined class lists in definition order, so an override class from a consuming module wins over the component's own style. Independent output drops that guarantee, while `cx` and the declarations inside each style keep their authored order. Development builds skip the sharing so names survive edits.

## Generated Names

Production class names are short and deterministic, including shared atomic rules, grouped classes, and `cx` combinations. Development builds use readable names throughout. Variables follow authored paths, such as `--z-color-brand`. Apply returned props rather than copying class names.

Production class lists add a style's identity class only when a selector interpolates that style. When combining independent configs, give each a distinct `id`.

```ts title="admin.config.ts"
import { defineConfig } from 'zyzz'

export const { style } = defineConfig({
  // [!code hl:2]
  // Prefix this config's classes, variables, and theme scopes
  id: 'admin',
})
```

The compiler reports incompatible generated names when it can detect them. Consumers own collision avoidance across separately built stylesheets.

## Delivery

Rebuild CSS and generated code together after edits and when changing modes. Precompiled libraries keep their output mode, so a consumer's config does not change published classes. See [Getting Started](/docs/introduction/getting-started) for setup.

A custom pipeline selects the mode when compiling style data. `Css.compile` has no filesystem or browser side effects.

```ts
import { Style } from 'zyzz'
import { Css } from 'zyzz/web'

const styles = Style.define({
  card: { color: 'red', padding: '8px' },
})

// [!code hl:2]
// Load output.css and apply output.classes.card
const output = Css.compile({ cssOutput: 'grouped', styles })
```
